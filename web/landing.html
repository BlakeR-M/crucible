Crucible github.com/BlakeR-M/crucible
Certificate of examination

AI finds bugs. Most of them are wrong.
This proves which ones aren’t.

A language model asked to review code will always find problems, and many of them read well and are wrong. The output looks like work and costs the reader more time than it saves. Crucible puts its weight on the second half of the job: every finding its agents raise is handed to three independent verifiers whose only instruction is to refute it, and only findings that survive a majority are reported.

09 / 16 survived
one recorded run: sixteen findings raised, seven destroyed by verification, nine reported

That run is public and checkable. On 2026‑08‑17 the arena reviewed its bundled demo target, a synthetic booking service carrying nine planted defects and a committed answer key. The planner cut the ground into six lanes and a hunter worked each lane blind to the others. Every finding went to three verifiers instructed to treat uncertainty as refutation, and two votes of three decided survival. Sixteen findings were raised. Nine survived. The run cost 27 US cents. The full hash‑chained ledger ships in the repository, and one command replays every decision in it on your machine.

How it is built

Authority is a document, not an assumption

An agent’s power is declared in one policy object, printed on screen during the run, carried in the record, and checked before any tool code executes. Containment is judged on the resolved path, commands are compared past argv[0], and a policy check that raises is a refusal. Refusals are first‑class events, shown with the reason and written to the record.

The record is tamper‑evident

Every run writes an append‑only ledger where each entry carries the SHA‑256 of the entry before it, so the file proves its own order and completeness. crucible verify recomputes the chain and replays every policy decision independent of the server that produced it.

The budget holds against work in flight

Every model call reserves its worst case before it spends and settles to real usage after, so a dozen concurrent agents can pass the same ceiling check and the run still stops where it was told to.

It reviewed itself, and lost

Pointed at its own source, Crucible reported a critical sandbox escape in its own policy engine: the command allowlist checked only the first word, so python -c handed the process arbitrary code with no shell metacharacter for the other guard to see. Reproduced end to end, fixed, and the regression tests are in tests/test_core.py, under the heading “an allowlisted binary is not an allowlisted behaviour”. The findings that stay open are published in docs/KNOWN‑ISSUES.md, because a system whose argument is showing what it threw away keeps its own list public.

Check it yourself

The repository is the product; this page is its cover sheet. Python 3.11 or newer, standard library only.

git clone https://github.com/BlakeR-M/crucible
cd crucible

# the recorded run above: recompute the chain, replay every decision
python -m crucible.cli verify docs/evidence/2026-08-17-demo-target-16-raised-9-survived.jsonl

# the whole arena, live in your terminal, keyless, spends nothing
python -m crucible.cli run demo_target --score   # with CRUCIBLE_OFFLINE=1 set

# every check in the suite
python -m pip install pytest && python -m pytest -q

The verify command exits 1. That is the tool being consistent: the exit code reports the review gate, and nine findings surviving means the demo target failed its review. An intact record of a failed gate is exactly what the file claims to be.
